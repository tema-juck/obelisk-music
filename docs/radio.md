# Internet radio (development branch)

Radio plays public, direct MP3 and AAC/HE-AAC streams through your system audio.
It needs **mpv**, but no Spotify account, Client ID, Premium subscription, or
Spotify Desktop. Radio is independent of Spotify Connect. This feature is not
part of the currently published v0.3.0-alpha.2 binaries.

## Install the optional backend

Install a current mpv from the [official installation list](https://mpv.io/installation/).
On macOS, Apple Silicon and Intel are supported; for example `brew install mpv`
if you already use Homebrew. On Debian/Ubuntu use your package manager's `mpv`
package (for example `apt install mpv` with your normal administrative process).
`mpv --version` must work in the same terminal that launches `obelisk`.
The Obelisk installer does not install mpv, change PATH, or bypass Gatekeeper.

Wheels and standalone binaries include the Python radio code, not mpv, libmpv,
FFmpeg, or codec libraries. Spotify and configuration commands still work without
mpv; trying to play radio gives an installation hint. Codec and audio-device
support come from your mpv installation. macOS Intel/Linux playback must be
verified on those systems before release; a macOS ARM build is not cross-platform
runtime verification.

## Browse and listen

Launch `obelisk` and press **R** (Shift+r) from the Spotify library. The Radio
screen has its own station table and persistent LIVE strip. Enter plays the
selected station. Selection highlighting and the ♫ playing marker are separate.
Loading is asynchronous; **v**, **c**, **Esc**, and **q** remain usable while a
request is pending. No station autoplays on launch or when reopening Radio.

| Key | Radio action |
| --- | --- |
| Arrows / j / k | Move selection (j/k respects `interface.vim_keys`) |
| Enter | Play selected station / load the next page |
| / | Focus station-name search |
| Tab / Shift+Tab | Cycle name, country, language, genre/tag, and results |
| Down in an input | Focus results |
| Esc in an input | Focus results, preserving edits |
| g | Genre browser; Enter selects a genre |
| 1–6 | Chill, electronic, rock, jazz, ambient, classical shortcuts |
| f | Add/remove selected favorite |
| v / c | Favorites / custom stations |
| a | Add a named custom HTTP(S) stream URL |
| Delete in Custom | Remove custom station and its saved favorite; `a` adds it again |
| Space | Stop, or resume at the live edge |
| x | Stop |
| + / - | Adjust radio volume by 5%; independent of Spotify |
| r | Reload the current list |
| ? | Scrollable help; Esc restores focus and selection |
| Esc / R in results | Stop radio and return to Spotify |
| q in results | Quit and clean up playback |

Inputs own all typing, including Space, j/k, q, and genre digits. Enter in an
input applies the filters and focuses results; it never starts playback. Search
is debounced 300 ms. Use an ISO two-letter country code such as `DE` or `US` and a
language name such as `english`. The tag input also accepts `lofi`, `house`,
`metal`, or `blues`; shortcuts choose the displayed broad genre. Filters combine
with AND. Clear a field to remove its filter. Pages contain at most 30 directory
records and load only through **Load more…**. Unsupported/unavailable records are
excluded with a count; a fully excluded page may still have another page.

The strip reports STOPPED, BUFFERING, PLAYING, RECONNECTING, or ERROR, actual ICY
StreamTitle metadata when supplied, and radio volume. It does not invent a song
name or display Spotify metadata as radio metadata. Live radio has no reliable
seek position. Space deliberately closes the stream and resumes live rather than
promising lossless pause/time shifting. Reconnect attempts are bounded (two retries
with 1 and 2 second backoff). Stop, station changes, and quit cancel retries.

## Saved stations

Favorites, custom stations, last station selection, and volume are stored in
`${XDG_DATA_HOME:-$HOME/.local/share}/obelisk/radio.json`, separately from
`~/.config/obelisk/config.toml` and Spotify keychain credentials. No audio, tokens,
or transient playing state are saved. Last station is remembered, never autoplayed.
The UI serializes updates; writes use a private temporary file and atomic replace,
with 0600 files and 0700 newly created directories. Symlink paths are refused.
At most 100 favorites and 100 custom stations fit in the 64 KiB state budget.

If data is corrupt or inaccessible, the original file is retained and saving is
disabled for that session. Repair it or move it aside yourself, then restart.
Directory browsing and playback can continue. An old favorite retains its URL;
if the broadcaster changes it, remove/re-add it from fresh discovery results.
Do not edit this file while the application is open or run simultaneous writers.

## Troubleshooting and boundaries

- **No mpv:** install it and make its executable available in PATH, then Enter.
- **Buffering/error:** check your connection and system audio output, try another
  station, or stop/retry. A broadcaster may restrict regions, listeners, or codecs.
- **Directory unavailable:** `r` retries; saved/custom stations remain accessible.
  Directory 429 cooldowns respect Retry-After independently from Spotify.
- **Rejected URL:** only public HTTP(S) destinations are supported. Local files,
  LAN/private/loopback/link-local hosts, embedded credentials, and unsupported
  schemes are refused. Use a direct MP3/AAC URL, not an HTML player, M3U/PLS/XSPF
  playlist, HLS manifest, or podcast file. HTTPS is preferred; plain HTTP has no
  transport authenticity guarantee.
- **Spotify is already playing:** pause it explicitly (Esc, Space, R) before radio
  starts. Radio controls never call Spotify endpoints. Leaving Radio stops its
  local process. External Spotify clients remain independently controllable;
  Obelisk cannot police audio started elsewhere while Spotify polling is suspended.

The guarded HTTP transport checks all DNS answers, connects to the checked IP
while preserving TLS hostname validation, and rechecks each redirect (at most
five). Proxy environment variables are intentionally ignored. mpv receives only
bounded audio chunks through stdin; configuration, scripts, sidecars, reference
loading, and network demuxer protocols are disabled. No station URL or metadata
is interpreted as a shell command or Rich markup. Stream bytes stay in bounded
memory/OS pipes, with no recording or audio file output.

## Directory and rights

Discovery uses [Radio Browser's documented search endpoint](https://docs.radio-browser.info/)
on separate HTTPS mirrors (`de1` and `nl1`), with name, tag, country code, language,
offset, limit, and hidebroken filters. Invalid entries and HLS/unsupported codecs
are skipped. The community directory does not confer rights to a stream. Listen
only where the broadcaster permits personal listening; obey its territorial and
usage terms. Obelisk does not host, rebroadcast, record, or download music to disk.

**Public-release blocker:** [Spotify Developer Policy](https://developer.spotify.com/policy)
§III.5 prohibits a product/service integrated with streams or content from another
service, and §III.7 prohibits mixing/overlap of Spotify Content with other audio.
Independent code, mode switching, and metadata isolation are technical safeguards,
not confirmation that this combined product is approved. Obtain explicit platform
policy clearance or resolve product separation before distributing the combined
Spotify/radio feature. This implementation does not claim policy compliance.

## Architecture and a future visualizer

`radio_http.py` owns URL/DNS/redirect boundaries; `radio_directory.py` owns read
pagination and cooldowns. `radio_models.py` contains only radio data;
`radio_store.py` owns private persistence. `radio_audio.py` provides an injectable
`AudioBackend` and supervises one mpv child plus private Unix-socket JSON IPC.
`radio_controller.py` owns Textual workers and I/O; `radio_ui.py` emits intents and
reuses NavigationTable/PlainText and existing semantic theme colors. `app.py` owns
source selection and gates Spotify polling/mutations while Radio is active.

mpv JSON IPC exposes properties/events, **not decoded PCM samples**. A concrete
future path is mpv's documented `--ao=pcm --ao-pcm-file=<private FIFO>` with
`--ao-pcm-waveheader=no`, `--audio-format=s16`, `--audio-samplerate=48000`, and
`--audio-channels=stereo`. A future native audio-output adapter would read the FIFO,
feed system audio, and tee bounded decoded samples to a visualizer. PCM AO replaces
mpv's normal audio output, so merely opening a FIFO does not preserve audible
playback. It needs a real playback sink and backpressure design. It must never be
connected to Spotify audio. No PCM extraction, recording, or visualizer runs in
the current application; the executed synthetic FIFO feasibility probe is recorded in
[radio verification](radio-verification.md).

## Manual acceptance (macOS and Linux)

1. Without Spotify variables/keychain access, launch and press R; browse genres,
   name/country/language/tag filters, empty results, and multiple pages.
2. Use a broadcaster's permitted direct MP3 and AAC stream. Confirm audible system
   output, actual metadata when available, volume, stop/live resume, and station
   switching. Verify one mpv child at most and none after quit.
3. Disconnect/reconnect the network; observe buffering/reconnecting/error, cancel
   during startup/backoff, then retry. Test invalid URLs, missing mpv, unavailable
   stations and directory mirrors without probing private network resources.
4. Save/remove favorites, add/remove a custom stream, restart, and verify selection
   and volume restoration without autoplay. Try corrupt state in a disposable XDG
   directory; ensure its bytes are preserved and saving is disabled.
5. At 120×35, 80×24, 60×20 and 40×12 in midnight/mono, test typing shortcuts, Tab,
   j/k/arrows, Enter, help restoration, source switching and quit during startup.
6. Return to Spotify: login, search F1/F2/F3, playlists, contextual playback,
   play/pause, next/previous, devices, and source isolation must remain unchanged.
