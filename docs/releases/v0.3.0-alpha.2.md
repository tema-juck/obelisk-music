# Obelisk Music v0.3.0-alpha.2

Prepared release notes; alpha.2 is not yet tagged or published. The package
version is `0.3.0a2`, corresponding to `v0.3.0-alpha.2`. Alpha.1 remains the
published baseline; no previous tag, release, or asset is replaced.

## F1 search playback fix

The F1 path previously sent a URI-list playback request. On affected Spotify
clients that request can return 204 while starting no playback. F2/F3 album
context playback continues to work. See the
[reported Spotify regression](https://community.spotify.com/forum/en/discussion/7552922/web-api-me-player-play-returns-204-but-does-not-start-playback-and-clears-current-playback-desktop).

F1 now uses the search result's album context and the exact selected track URI as
its offset, using the existing supported playback endpoint. It sends one
serialized mutation. It does not infer an album position from search order or
disc-relative track numbering, retry ambiguous failures, or try alternative
playback after a rejection. Missing album metadata provides F2 navigation guidance;
rejected playback provides an actionable error. Spotify's subsequent playback
read updates Now Playing.

F2/F3 preserve their original album offsets. Focus, row selection, typing
shortcuts, Spotify Connect targeting, token recovery, and shared rate-limit
cooldowns remain in use. Search, artist/album browsing, themes, and configuration
from alpha.1 remain supported. No new configuration or OAuth scopes are needed.

**Playback behavior:** the selected track starts in album context. Spotify may
continue through the album after that track finishes. Obelisk does not edit the
queue or add automatic playback mutations to stop that continuation.

## Installation and upgrading

Once alpha.2 is fully published, the reviewed installer can select:

```sh
sh install.sh --version v0.3.0-alpha.2
```

`--prerelease` selects the newest published prerelease. Until alpha.2 is published,
use alpha.1 from the README instructions. Existing TOML configuration and keychain
credentials are preserved. Python, uv, sudo, and Homebrew are not needed for a
standalone installation.

Planned assets (not download links):

| Platform | Archive |
| --- | --- |
| macOS Apple Silicon | `obelisk-v0.3.0-alpha.2-darwin-arm64.tar.gz` |
| macOS Intel | `obelisk-v0.3.0-alpha.2-darwin-amd64.tar.gz` |
| Linux x86_64, glibc | `obelisk-v0.3.0-alpha.2-linux-amd64.tar.gz` |

Each archive contains `obelisk`, `LICENSE`, and `build-info.json`. The publisher
generates `SHA256SUMS` only after validating the complete three-archive set. Use
the [checksum instructions](../installation.md#verify-release-checksums-manually)
before installing. macOS builds use ad-hoc signing without Developer ID
notarization. Linux targets the Ubuntu 22.04 glibc baseline, not Alpine/musl.

## Verification and release gates

The merged hotfix baseline is `589c06e4156f19dfd5d798960fd6f2efcc56158a`; its
[GitHub CI run](https://github.com/tema-juck/obelisk-music/actions/runs/42749133093)
passed. The alpha.2 preparation commit still needs its own green CI after review.
Automated coverage includes distinct selected URIs, pagination, input focus,
unavailable tracks, F2/F3 offsets, device targeting, cooldowns, and failed or
ambiguous mutations. Clean wheel smoke exercises mocked F1 playback and Now
Playing without live credentials.

After separate tag/publication approval, the tag-triggered release workflow must
pass quality checks and all three native build/smoke jobs. Build jobs are
read-only; only the publisher has write permission. It checks archive integrity,
version, architecture, source commit, toolchain and checksums, verifies tag
immutability, uploads a complete draft, and verifies assets before publication.

Before live sign-off, test F1 with a non-first result and a result on page two,
confirm the chosen song and Now Playing, verify typing does not start playback,
and repeat F2/F3 with the same account/device. See the
[full live checklist](../music-experience.md#live-smoke-checklist).
